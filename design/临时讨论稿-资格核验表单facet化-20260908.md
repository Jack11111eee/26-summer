# 临时讨论稿：资格核验表单 facet 化（gate 表单 v2）

**日期**：2026-09-08　**状态**：设计收敛完成，SSOT §16.1 修订稿待授权　**范围**：模块二 §16.1 表单链
**触发**：实测评发现资格核验表单下拉框无选项（P0 bug，已修，见 §8），暴露更深层问题——gate qualification items 未归一，候选人被迫对同质事实面逐条作答。

---

## 1. 问题

全库 gate=1 的 qualification std_name 约 150 个，同一事实面（最高学历 / 院校档次 / 英语等级 / 专业范围 / 年龄 / 出勤天数……）存在大量近重复措辞。典型实测评场景：候选人同场需逐一回答「本科及以上学历」「硕士及以上学历」「211硕士及以上学历」「计算机相关专业」「相关专业」「相关专业背景」「机器视觉/数学/电子计算机等相关专业」——实为 3 个事实面（学历、院校档次、专业范围）。且当前实现将每个 qualification item 渲染为该 item 专属的二值下拉（是/否），信息密度与体验双差。

另一个语义粗糙点：所有 experience 年限项共用同一个「工作年限（年）」数字（`server/services/forms.py` base 字段；`_gate_check` 消费），即「SLAM 融合开发经验 ≥ 5 年」拿候选人**总工作年限**判定。

冗余的**根在上游**：模型 items 本身未归一（「相关专业」与「相关专业背景」来自不同 JD）。词典治理第 3 层（126 名身份迁移组）冻结待逐条裁决，这批 qualification 近重复大概率混在其中。本方案定位为**下游兜住**，不抢上游治理的位置。

## 2. 用户裁决（2026-09-08，五条）

1. **收集形态**：紧凑结构化表单（非对话式 + 抽取）。对话式收集（P-form-facts，§16.2 简历链同构）留作后续阶段复用同一 facet 事实模型，不在本期范围。
2. **专业范围类**：不做 LLM / 文本解析，渲染为**勾选组**——一次读完所有专业相关断言，勾选符合项。
3. **长尾 fallback**：规则分类不出的 qualification item，原样降级为勾选组陈述（最坏情况 = 现行为换更好的控件，永不 block）。
4. **experience 标签**：改为「与岗位相关的工作年限（年）」，只改文案，不拆分、不动模型。
5. **P0 bug**（下拉空白）：允许单独先修——已完成（见 §8）。

## 3. 方案：facet 归并 + 确定性派生

### 3.1 facet 模型

渲染时，gate qualification items 按**确定性规则**（关键词词表 + 内嵌数字解析，纯函数、无 LLM）归并为少量候选事实面（facet），每个 facet 一个收集控件：

| facet | 控件 | 答案形态 | 派生规则 |
|---|---|---|---|
| `education_degree` 最高学历 | 有序枚举（专科/本科/硕士/博士） | 单选 | item 阈值 ≤ 候选人学历 → 通过；学历类断言取措辞中出现的**最低学历档**为阈值（宽读法，如「学士或硕士学位」→ 本科） |
| `school_tier` 院校档次 | 有序枚举（985/211/其他） | 单选 | 候选档 ≥ item 要求档 → 通过（985 ⊆ 211，985 毕业生满足 211 要求） |
| `english_level` 英语等级 | 有序枚举（六级/四级/无） | 单选 | 同上，等级比较 |
| `number_range` 数值断言 | 数字输入 | 数值 | std_name 内嵌数字解析出阈值与量纲（如「年龄30岁以上」→ 阈值 30 岁），数值比较；解析不出 → 降级 fallback 勾选组 |
| 专业组 + 二值断言 + 长尾 fallback | **勾选组**（勾 = 是） | 0..n 勾选 | 勾选项 = 该 item 真；未勾 = 否（`_gate_check` 现有「是」真值表直接命中） |

`years_of_experience`（base 字段）保持独立数字输入，标签改为「与岗位相关的工作年限（年）」，`_gate_check` 消费逻辑不变。

**渲染效果对比**（本实测评场景）：7 个二值下拉 → 「最高学历」+「院校档次」两个枚举 + 「专业/资格项」一个勾选组（四条专业断言并列勾选）+ 原有工作年限，共 4 项。

### 3.2 派生管线（插入点固定）

```
facet 答案（候选人提交）
  → validate_and_submit 的必填/枚举/长度校验
  → 【新增】facet 派生：展开为逐 item 真值 {std_name: true/数值}（纯函数）
  → 现有 _gate_check 真值表消费（True/"true" 已在真值表内，零改动）
  → gate 行写入 / GATE_EVALUATED（不变）
```

- 直接映射项（勾选组）：payload 即逐 item 真值。
- 派生项（学历链 / 档次链 / 英语链 / 数值断言）：派生结果为 `true/false`，命中 `_gate_check` 现有真值表（`True`, `"true"`, `"是"` 等）。
- 分类的确定性规则随快照落库（见 3.3），**同一次测评内规则与渲染时的快照一致**，不因代码后续演进而漂移。

### 3.3 快照 v2 与 v1 兼容

- `schema_version`: v1 → **v2**。v2 快照 fields 每字段增 `facet` 键；宿主 item 的派生参数（阈值、档位）随快照落库。
- **v1 兼容**：已 open 的 v1 rendered 实例走旧链完投（v1 payload 本就是逐 item 二值，`_gate_check` 原样消费），不迁移、不转换、**不因升级重渲染**（快照不可变语义）。
- form_instance 表结构不变（快照自版本化，无需 ALTER）。
- 渲染白名单 `_FIELD_WHITELIST_KEYS` 需增 `facet` 键（GET /forms/{id} 响应同步）。

### 3.4 payload 两段式

payload_json 建议存两段：**收集到的 facet 原始答案**（如 `education_degree: "硕士"`、勾选列表）+ **派生结果**（逐 item 真值）。两段均落库，审计可复现：从 facet 答案 + 快照内派生参数可复现每个 item 的 gate 判定。具体键名实施时定，不进 SSOT。

## 4. 不变量（本次改动的收口边界）

- **派生层插入点固定**：`validate_and_submit` 枚举校验之后、`_gate_check` 之前；派生函数纯函数、无 LLM、无新表。
- **不动**：gate 行结构（`question_score`）、aggregation 消费、报告页、管理端、`_gate_check` 本体与真值表、form_instance 表结构。
- schema 快照不可变语义、幂等/revision 生命周期全部沿用。

## 6. 测试口径

## 7. 开放点（实施前收口，不阻塞授权）

1. **「985/211院校」类并读词**：默认宽读法（= 211 要求档，任一名校满足）；实施词表时逐词确认。
2. **数值断言解析词表**：「年龄30岁以上」→ 阈值 30 + 量纲岁；“每周出勤4天及以上”→ 4 + 天/周；解析不出降级勾选组。正则 + 小词表，实施时定稿。
3. **英语族内外分**：等级词（四级/六级）进 english_level；能力词（口语/听力/写作）为独立断言进勾选组——边界实施时定。

5. payload 键名、控件样式（下拉 vs 分段选择）、派生函数命名——实施细节，不进 SSOT。

## 1. 评分链（v2.0 最终确认）

```
原始回答证据 → 独立终局评分 score_final（P-score，temperature≈0，按 raw_hash 回捞原文）
→ item 内证据裁决 → 固定 item.weight 加权 → 画像报告
```

- **score_live 只用于过程性选题与难度导航，不参与最终分数**；与 score_final 的差值仅用于偏差分析与 bad case 候选，不写回分数；
- 客观题代码判分（answer_key 为空 = 题库缺陷，判题库无效而非满分）；**命中 = 5 分 / 未命中 = 1 分，与 §7 `(score−1)/4` 归一化同口径**；evidence_quote 取候选人回答前 60 字符（展示截断固定规则，非开放参数，`_OBJECTIVE_QUOTE_LEN`）；
- **客观题答案规则结构化（2026-09-09 新增，SSOT §17，作废「整串说明文本作答案键 + 字面包含匹配」旧口径）**：不再以「一整段说明性 answer_key 是否整串出现在回答中」为判据。答案键必须标注**答案规则类型** `answer_rule_type`（`exact_options`（封闭选项）/ `numeric`（数值，含精度/容差）/ `symbolic`（符号表达式，如五元组）/ `alias_set`（有限别名集合）），规则参数结构化存储（如 `{"options": [...], "aliases": {...}, "value": ..., "tolerance": ..., "operator": ...}`）；判分器按规则类型分派。标点/空格/全半角/Markdown 归一化按题型处理（数学符号不全局删除——语义变化风险）；列表型答案必须显式标注 `match_semantics: all_of | any_of`（全部要点都要 / 任一等价答案皆可），不再用 `|` 连接列表后靠正则分支猜；否定句、错配关系、矛盾陈述不得仅凭关键词存在判正确；无法可靠判分的自由表述进复核路径不强行给最低等级；
- **正确性与能力等级分离（2026-09-09 新增，SSOT §17）**：答题正确性（answer correct）与能力等级（competency level）是两回事。客观题命中得 5 分仅表示「答案正确性：正确 + 该题锚点区间内最高置信」；基础概念题答对不自动证明独立实践/专家水平，基础题未展示高阶能力不证明缺乏高阶能力。item 最终等级由多题证据按锚点区间裁决（§4），单题不超过其 observable_level_max（模块二 §1.4）；
- **主观评分锚点约束（2026-09-09 新增，SSOT §17）**：P-score 评分理由必须受题目 rubric 与锚点约束——输出至少含「命中的锚点或要点 / 对应回答原文 / 必需但缺失的要点 / 明确错误或反证 / 尚未展示的更高等级证据 / 评分或无法评分原因」；不得增加题干与 rubric 中未要求的必要标准（「没提某额外技术」不是扣分理由）；更高等级证据不足与本题答错分开说明；替代方案满足任务目标和约束的不因未用指定工具扣分；Lv5 是否需要领导他人以该能力锚点为准，不得让所有技术题通过「没带团队」限制最高等级。输出严格校验类型/范围/证据引用/锚点编号；非法结果进明确失败或复核路径；
- 终局评分失败且无可信结构化结果 → 报告 `FAILED`，不得生成 0 分正常报告；
- 报告生成**必须前置**终局评分：正常 UI 主链 score→report 由服务端串行链执行（`POST /report` 内部先 score 后 report，前端无需显式调 `POST /score`；`/score` 端点保留为显式入口，completed 会话被服务层护栏拒绝 409）。

### 1.1 跨消息证据定位禁令（2026-09-09 新增，SSOT §12.5）

多轮回答下不得将全部消息拼接成单文本后定位引文、并将 source_message_id 统一填为最后一条用户消息（已确认缺陷：第一轮回答的引文被标成第二轮来源）。定位必须**在各原始消息内分别进行**，偏移量相对该消息原文；跨消息引文拆为多片段（每段绑定各自 source_message_id）；找不到原文时标记定位失败（woffs/offset 为 NULL），不得以仅有 quote_hash 的记录冒充已定位证据；摘录、消息、题目、会话的归属关系都校验。

## 2. 拒答（REFUSED）

```
score_value = 0；score_state = REFUSED
```

- 0 是特殊状态值，**不是能力量表 1 分**；
- **拒答只进入行为聚合与完整度聚合，不进入能力等级聚合**：item 最终等级由有效能力证据决定，后续有效回答可以改变等级；
- 拒答事件永久保留，报告单独展示拒答次数与位置；
- 涉及受保护信息或合法隐私质疑的拒答 → 合规/人工处理，不直接记 0。

**实施注记（2026-09-06，2026-09-09 修订，SSOT §18）**：score_state 枚举位 `INSUFFICIENT_EVIDENCE / NOT_ADMINISTERED / INCOMPLETE` 本期**不产出**（by-design）：现终态由 REFUSED（拒答）、INVALIDATED（题库无效）、INSUFFICIENT_EVIDENCE（评分输出非法 U5b 起、末轮特殊观察状态 2026-09-09 起——模块二 §6.1 凝结规则）与聚合层 PROVISIONAL/NO_VALID_OBSERVATION + missing_warnings（§5，IMPUTED 一位随 2026-09-09 补算作废而停用新产出）语义等价覆盖；NOT_ADMINISTERED 的潜在场景（派发未答实例进 finalize）走 §5 缺失路径，不做区分。枚举位保留供校验与后续生产。

## 3. 分母规则

| score_state | 正常能力分母 | 缺失/警告 |
|---|---|---|
| SCORED | 进 | 否 |
| REFUSED | 不进（只进行为/完整度） | 单独记录 |
| INSUFFICIENT_EVIDENCE / NOT_ADMINISTERED / INVALIDATED / MODEL_UNCERTAIN / INCOMPLETE | 不进 | 是 |

系统错误与题目无效不得转成普通低分；全部无效观察 → `NO_VALID_OBSERVATION / HUMAN_REVIEW_REQUIRED`，不得补算出确定分。

**question_score 结构（SSOT §12.4）**：统一 `score_final`（废弃重复列 `final_score`，迁移合并旧数据）；新增 `item_id / score_state / measurement_target / rubric_version / evidence_spans_json / scorer_version / human_override_score / human_override_state / override_reason / reviewer_id / reviewed_at`；综合题一题多 item：(question_id, item_id) 多记录合法；**`scoring_batch_id`（2026-09-09，§6.1）**。

## 4. item 内多题合并与综合题裁决（2026-09-09 修订：量表统一前置）

普通题与综合题先转统一测量记录再裁决：

```
item_measurement(question_id, item_id, observed_level, evidence_refs, measurement_source: ordinary|integrated)
item_final_level = adjudicate(ordinary_measurements + integrated_measurements)
```

- 普通最低测量资格先检查（综合题不能替代普通题第一次测量）；
- **裁决前置：量表统一（2026-09-09 新增，SSOT §19）**——裁决前必须先将每题测量记录归一到统一锚点语义——每条测量记录携带 `measurement_target + anchor_level（锚点档） + observed_level`；不同锚点档（基础理解/应用/优化）的证据**不直接互相比较**，更不得跨尺度计算极差（easy[2,3] 与 medium[3,4] 题目回答质量差异是量表差异不是候选人矛盾）。**作废**「对 item 内全部题目的 observed_level 直接求极差」的旧实现（CNN 案例已确认：easy 答对得 5、medium 分析得 3，极差 2 触发伪冲突取低——量表混用产物）；阈值常量 `ADJUDICATE_CONFLICT_THRESHOLD=2` 保留为冲突判定的输入之一（仅在可比较锚点档上生效，集中 `config.py`）；
- **裁决算法（修订）**：①相容证据（同锚点档或记录声明相容）按锚点区间合并——共同支持更高层次判断；②冲突判定仅对**同一 measurement_target、可比锚点档**的证据进行；实质矛盾（同一目标上相反陈述）才触发冲突；③冲突未解决 → 该 item 显示待复核，**不以「保守」为理由自动形成确定低等级**（旧 `min(levels)` 取低留标记**作废**——冲突归冲突，不产生替代性确定值）；④明确自我纠正的回答保留纠正过程（纠正前后都算）；未明确解决的矛盾陈述不得任取较新/较高者；⑤同一证据被多处引用只算一份独立支持；⑥最终等级必须能列出所满足的必要锚点与其来源题（完整审计级——实施可分层：第一层只在报告 item 行关联来源题，第二层才做锚点分解展示）；
- 不按来源加权、不按题数重复乘 item.weight；共享 evidence span 只影响证据解释、不折扣不自动复制评分；
- 综合题可作为最高等级证据来源（受其 rubric 约束）；综合题整体 `ITEM_INVALID` → 所有绑定 item 综合结果无效、移出分母；单 item 证据不足不影响其他 item 独立评分（一题多 item 记录写入 question_score，`(question_id, item_id)` 合法）；
- **不采用以下捷径**（即使冲突或样本不足）：简单平均、直接最高、直接最低、只按题目来源加权。本期综合题仍沿用现有范围（I=0 不排期），测量记录格式保持兼容。

综合题第二题决策表：剩余合法联合 target 为主触发；第一题整体无效可触发；仍受最多 2 题、题库版本匹配、session 状态约束；全场超时不再激活。

## 5. 缺失、未测量与聚合（2026-09-09 重大修订：作废比例补算）

```
O = 全部 score_state=SCORED 的 item 级测量
M = 未测量集合（无有效直接观测的正式范围内能力项）
未测量项：无个人等级，标记 UNMEASURED
```

- **比例补算（IMPUTED，以已测能力加权均值 r 为无证据能力统一生成等级）作废**（2026-09-09，SSOT §20.1）：Python 作答不能证明沟通能力、其他算法与经验背景处于同一等级——345 项无证据能力统一标注 3.41 级并占报告权重 91.88% 的实测形态，判定为已知缺陷而非设计特性。**未测量能力显示「未测量」，不生成个人等级，不进实际表现雷达、优势、短板与正式综合分**；不用 0 分代替缺失；不将其他能力的分数重归一化后仍称「完整岗位综合分」；
- **过渡期兼容（仅存量报告回放）**：历史报告 JSON 中已存在的 IMPUTED 数据按当时规则解释生成，只读展示（标注旧口径——补算值参与总分构成），**不得据此重算历史成绩**；
- `O = ∅` → `NO_VALID_OBSERVATION / HUMAN_REVIEW_REQUIRED`（不变）；
- **未测量比例超阈值 → PROVISIONAL + HUMAN_REVIEW_REQUIRED**（阈值沿用裁决值 0.2：正式范围内未测量项占比 > 0.2 → 不能形成完整综合分，复核原因注明「未测量比例过高」，不得混成「题目冲突」或只给列表后段条目标 human_review；常量 `IMPUTE_RATIO_THRESHOLD` 随实施更名为 `UNMEASURED_RATIO_THRESHOLD`——§7 总分门控同源）；
- required 与 qualification 不适用（前者缺失 → §6，后者本就独立展示）；
- 若未来需要抽样估计，另行设计、验证并明确标注——**本期不引入未经验证的估计模型**。

### 5.1 测评范围（assessment scope，2026-09-09 新增，SSOT §20.1.A）

「模型中出现过的能力」≠「本测评评价的能力」。每个测评版本在发布时**冻结正式测评范围**，开考时不可变：

- **冻结字段**：正式计分能力项集（item_id 清单）、各项 required_level、权重、measurement_target、最低证据要求、可使用题目及难度路径、资格条件集、策略版本；
- **范围区分三类条目**：正式计分项（participant）、岗位背景资料项（reference-only，不占权重、不出雷达、不进总分）、表单事实项（form facts）；
- **发布时确认、开考冻结**：范围随模型 confirm 显式确定（管理端可在模块一人审时标记何者入正式范围），源 JD 与来源证据保留可追溯（为何纳入/排除）；
- **两个禁止事项**：不得在测评结束后只保留问过的能力把覆盖率变 100%；不得前端隐藏未测项却让它们继续参与总分；
- 不同测量目标需要时建不同**测评版本**（模型版本 + 范围标记），**不得**单凭关键词自动拆岗或删条目；
- 存量模型无范围标记时：默认全部 gate=0 能力项为正式计分范围（与现行行为一致，无破坏迁移）。历史报告无范围快照时按其 item_details 口径解释并注明口径限制。

## 5.2 评分批次与历史修订（2026-09-09 新增，SSOT §20.2.A）

- **评分批次（scoring batch）**：`question_score` 增 `scoring_batch_id`（不可变版本标识）；每份报告绑定具体评分批次；新评分结果**追加保存**（不再删除旧评分行后重插——`score_session` 的 DELETE+INSERT 循环作废，该形态即使 report_json 保留旧版本也会替换评分证据链，审计断裂）；
- 原始消息、原题目、旧评分、旧报告、旧异议全部保留；修订记录说明修订原因、规则版本、影响结果；
- 资格覆盖采用可追溯的有效版本（`ORDER BY created_at` + 明确版本选择语义），不使用无 ORDER BY 的 `LIMIT 1`；
- 表单修订使用实例标识 + revision 查询/更新/消费，不更新同一实例的全部版本；表单实际评估使用的 schema 版本写入结果（不统一写当前全局版本）；
- 保存真正使用的 rubric/scorer/测量目标版本（不再长期硬编码 `'v1'` 与空目标）；
- **重算入口**：用户刷新与普通「生成报告」幂等（不重复评分）；历史纠错走**管理员修订流程**——先只读预演（列出受影响题目/分数/覆盖/文案），确认后生成正式修订版；不把旧会话套到后来重建的新岗位模型；旧题无法支持新量表时明确说明「不可完整重建」而非制造新成绩；
- 后台任务绑定明确的生成任务或报告版本：旧任务超时后返回不得更新新任务的占位报告（重试、评分批次、最终报告归属一致）。

## 6. required 缺失与临时报告

```
report_status = PROVISIONAL；review_status = HUMAN_REVIEW_REQUIRED
```

- 不触发补测；
- **人工确认后可发布为正式报告，必须由管理员明确点击发布**，不自动发布；
- 报告必须列出：缺失 required item、缺失原因（拒答/系统错误/题目无效/模型不确定）、哪些结论未经人工确认；
- required 缺失与未测量（§5）、题目冲突（§4）的复核原因**分别记录**，不得互相混同。

## 7. 总分与门槛

```
总分 = Σ(item.weight × normalized_item_score) × 100
normalized_item_score = (actual_level − 1) / 4（1→0、5→1；作废旧实现 score/5 隐式口径）
gap = required_level − actual_level
门槛项（gate）：达标拿满 / 不达标 0，UI 红绿标签单列，不进 1–5 评分
```

大类 7:3 已体现在 item.weight 中，聚合**不再二次乘大类比例**。

**完整性门控与精度（2026-09-09 新增，SSOT §20.3）**：

- **总分仅在正式计分范围满足最低测量要求（未测量比例 ≤ 阈值 0.2，§5）且关键争议已解决时生成完整值**；否则该场报告**无综合分**（`total_score = NULL`），各接口与消费页面（历史列表、报告页、admin）必须支持无综合分展示，不得以 0 分或占位值冒充（`report.total_score` 列改 NULLABLE——2026-09-09 前 NOT NULL 默认 0.0 的旧库行为作进化处理）；
- **未测项得分为「无结果」而非 0**；缺失不得偷偷缩小分母；
- 资格事实独立展示，不进入能力指数（不变）；
- **精度规则**：内部统一精度与舍入规则；权重归一化的累计舍入误差不得全部压给单个最大权重项；报告 JSON 保留可复算的原始贡献（保留足够精度）；总分从未提前舍入的贡献统一计算、**最后一次舍入**；展示层逐项贡献四舍五入后相加不等于显示总分时注明「显示值存在舍入差」，不为凑显示总分修改任何能力的实际等级。

### 7.1 覆盖率口径（2026-09-09 新增，SSOT §20.4）

报告分别展示以下五个指标（取代单一 `coverage_ratio` 观察/可测比例——该口径将必备项排除在分母外为已确认缺陷，**作废**）：

1. **作答完成情况**：已回答题数 / 计划或允许的题量；
2. **能力观察覆盖**：正式范围内，有有效直接观测（存在 SCORED 记录）的不同能力项数 / 正式范围能力项总数；
3. **有效测量覆盖**：满足该能力最低证据要求的能力项数 / 同分母；
4. **权重覆盖**：达到有效测量要求的能力权重 / 正式范围总权重；
5. **必备项覆盖**：已满足测量要求的必备项 / 必备项总数（单列）。

规则：同一能力两道题只计一个能力项；必备项不从分母排除；资格、经验事实不进入对话能力覆盖率；未出题、拒答、题目无效、证据不足等原因分开显示；被排除或未测项保留在开考前确定的分母中（不得事后删项抬高覆盖率）；分母为零显示「不适用」而非 0%/100%。**区分「存在一条 SCORED 记录」与「已充分测量」**——11 项有评分记录不代表 11 项都满足证据要求。

## 8. 报告（五段式 + v2.0 发布契约，2026-09-09 修订）

①**顶层结果摘要**（总分或无综合分原因 + 状态 + 资格核验摘要折叠——49 项级资格详情默认折叠、展开按类别分组逐条展示，模块二 §10 四状态）②**雷达图**（required 灰 vs actual 蓝；只绘制已直接观测项；IMPUTED 项不进雷达——§5 已作废补算；轴由测评版本预先确定、不按数据库返回顺序截取，轴绑定 item_id 防索引错位；缺失值不按 0 绘制；观测项不足时不强行画雷达改逐项对比；web-next 为自研 SVG 实现）③**优势/短板/建议**（代码排序：优势=gap≤0 中权重前 3；短板=gap>0 中 gap×weight 前 3（actual<required，低于要求）；只基于可用、无未解决争议的证据；未测项进「尚未覆盖」不算短板；争议项进待复核；LLM 只写文字且只能基于给定短板项；无足够证据显示「暂不足以判断」不显「没有短板」；每条结论关联具体题目和证据；文案限定为本场证据，不泛化为永久能力特征）④**逐题回顾**（score_final + 证据 quote + 来源定位；实际题号 seq、包含全部实际出过的题、实际呈现的全部轮次、正确性/能力证据/最终结论分别展示、过程参考值（score_live）与终局结果分列）⑤**逐项明细**（放最后；正式范围能力默认视图 + 筛选；「得分」列明确为观测等级或综合贡献；差距=要求−表现、正值未达标 0 达标 负值超出；无数据/拒答/无效/待复核分别显示；长表筛选不改变覆盖率与总分；行内「异议」按钮）。

**报告顺序与锚点（2026-09-09 确认）**：五段固定顺序——摘要 → Radar → Summary（③）→ Review（④）→ Details（⑤）；长明细放最后；顺序同时适用正常报告、暂定报告与无综合分报告；页面锚点使用稳定标识（section id），不按「第几个 section」定位（避免调整顺序后跳错位置）。「达到要求」与「超出要求」用词区分。

### 8.1 报告状态机、发布与校验

```
report_status: GENERATING → PROVISIONAL | READY → PUBLISHED | FAILED
review_status: NONE | REQUIRED | IN_PROGRESS | CONFIRMED | CLOSED
```

**发布前一致性校验（代码，七项为基础 + 2026-09-09 语义深化）**：数字可重算（从未提前舍入的贡献统一计算）；item.weight 总和一致；引用 question/message 属于该 session；model/version 与快照一致；无效题/系统错误未进正常分母；缺失/REFUSED/required 警告与结构化状态一致；文案无录用判断表述。**校验语义升级（2026-09-09）**：仅验证「字段存在/清单存在」的浅检查不算通过——至少含：每条评分绑定评分批次与题目一致；引文可定位到对应消息（source_message_id 归属正确的轮次）；覆盖率按能力项计数守恒（资格/经验不进对话能力分母）；无效/拒答/缺失未被当成正常低分；综合分仅在完整性条件满足时存在；雷达、Summary、Details 用同一组结果；优势短板不含未测或未解决争议项；报告文字无结构化结果中不存在的确定性结论；复核原因与报告状态一致；发布不清除仍然存在的完整性限制。

**执行性补充（2026-09-09）**：`generate_report()` 返回 FAILED 不抛异常——调用方（后台任务）必须检查返回值的 report_status，不得在 FAILED 时记 TASK_SUCCEEDED（事件状态与真实报告状态矛盾为已确认缺陷）。

**发布语义（2026-09-09 修订）**：报告状态三维度——是否生成成功 / 测量是否完整（有无争议）/ 是否已人工发布。**发布不能补出不存在的证据**：部分报告可以在明确标注范围限制的前提下发布（PROVISIONAL 正常发布路径），但不得因发布而变成完整测量或获得完整综合分。发布请求必须携带明确复核结果（review_outcome）与必要理由；默认值直接 CONFIRMED 的免审直通**作废**（发布需显式选择结果）；发布动作不改变证据完整性；记录执行人、时间、依据与报告版本。

**接口一致性（2026-09-09）**：报告读取序列化出口统一——按会话（GET by-session）与按 report_id 读取返回一致的 report_status/version/完整性信息；结果快照（report_json）与生命周期元数据（report 行列）职责分离但状态必须一致（发布动作更新表列时同步更新 JSON 内复核字段，不得一处新一处旧）。

人工复核字段：`review_request_reason / reviewer_id / review_note / review_outcome / reviewed_at / publish_confirmed_by / published_at`。

**重复触发护栏（P0 成功标准 5）**：`POST /sessions/{id}/report` 在会话已存在报告且报告处于生成中（`GENERATING`）或终态成功（`PROVISIONAL`/`READY`/`PUBLISHED`）时返回 409（`REPORT_GENERATING` / `REPORT_ALREADY_GENERATED`），不重复触发评分/报告；报告为 `FAILED`（后台链失败）或无 report 行时允许重新入队（202），作为失败重试路径。

**死任务接管与看门狗（2026-09-08 事故登记）**：`GENERATING` 为占位态，其 409 护栏仅保护**真在途**任务——最新 `GENERATING` 行行龄超 60 分钟（常量落 `api/assessment.py` `_STALE_GENERATING_SECONDS`）视为死任务，`POST /report` 放行**版本化接管**（写新 version GENERATING 行，不覆盖旧行；`created_at` 解析失败保守维持 409）；60 分钟内维持 409。后台串行链整体处于**看门狗**下（内层线程执行 + `join(60min)`，与接管阈值共用同一常量），超时写 `TASK_FAILED` 事件 + `FAILED` 行；任务异常兜底链自身失败不静默——至少落 stderr 进程日志。**执行纪律**：后台链任何「另开连接写库」的步骤之前主连接不得持有未提交写事务（2026-09-08 事故：bad_case INSERT 挂主 conn 末尾 commit 持 RESERVED 锁进 LLM 调用 → 全进程 `database is locked`；修复为独立小事务 + `generate_report` 全函数 `finally` 兜底 rollback）。前端「重新生成」按钮必须走 `POST`（GET 只会读回旧状态）；409 分支分派——`REPORT_GENERATING` 并入轮询、`REPORT_ALREADY_GENERATED` 重取、`SESSION_NOT_COMPLETED` 明确文案。

**生成进度透传（2026-09-09 新增）**：GENERATING 占位行 report_json 语义扩展为「瞬态进度区」——串行链运行期可携带 `progress` 键（`{stage, done, total}`；stage ∈ scoring｜report：评分子步逐题推进 done=i/total，报告子步一次写满，skip_scoring 幂等重链路径同样有进度）。进度写入为独立小事务 + `WHERE report_id=? AND report_status='GENERATING'` 钉行守卫（看门狗翻 FAILED 后僵尸线程进度写自然 no-op）；写失败只落 stderr 不杀链。**终态行永不携带 progress**。前端生成中态增进度条 + 分步文案，无 progress（旧存量占位行）回退既有静态文案。无表结构、端点、轮询协议变更。

**流程**：评分完成 → 聚合与校验 → 生成（PROVISIONAL 或 READY）→ 有人工复核要求则等待 → 管理员 `POST /reports/{report_id}/publish` 明确点击发布（携带 review_outcome/note）→ PUBLISHED。报告表 version 列版本化（重复生成不 DELETE 覆盖旧行）；报告任务异常 → FAILED 行 + TASK_FAILED 事件显式可见（不静默）。

## 9. 异议与人工复核

- 候选人逐分异议 → feedback 表，**不自动改分、不触发报告重算**，只进人工处理与质量数据；
- 人工复核可查看证据、覆盖结果并决定报告是否发布；不修改原始评分（原始结果与人工结论以 override/复核记录叠加，不擦写）；
- 人工覆盖 gate 或认定题库/模型失效 → **二次人工确认**，必要时废弃当前测量另行安排；
- 管理员查看候选人原文/trace 需留访问审计事件（REVIEW_ACCESSED）。

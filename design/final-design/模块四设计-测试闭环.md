## 1. 三大标准落点

| 标准 | 落点 | 实现 |
|---|---|---|
| ①全链可审计 | report → session → model/version → question → message → score → trace，经 `trace_link` 统一关联表闭合；P8 trace 查看器 | trace 查看器（admin）+ trace_link |
| ②反馈可回溯 | 候选人逐分异议 → feedback（不改分）；admin 审核标记 bad case；双分背离自动候选；通用系统建议 → suggestion（独立通道，§1.1） | feedback 表 + bad case 流 + suggestion 表 |
| ③有测评标准 | b+c 评测；eval/ 目录独立可迁移；**联调全绿后最后做** | 评测运行器 + eval_results |

### 1.1 意见反馈通道（suggestion，2026-09-08 新增，SSOT §22.1）

**表 `suggestion`**：`suggestion_id PK / user_id NOT NULL REFERENCES user / text NOT NULL / status CHECK('pending','reviewed') DEFAULT 'pending' / created_at / review_note / reviewer_id / reviewed_at`（审计四列与 feedback Phase 5 模式对齐）。**独立于 feedback 逐分异议管道**——不复用表（report/item NOT NULL 列放开需 12 步表重建，管理端 join/事件挂靠/bad_case 管道对建议形态不适配，2026-09-08 已否决）。

**端点**：候选端 `POST /api/assessment/suggestions`（text 必填，长度上限 `MAX_SUGGESTION_LENGTH=2000` 进 config）+ `GET /api/assessment/suggestions`（本人历史含 status，让用户看到处理进度）；管理端 `GET /api/admin/suggestions`（status 过滤）+ `POST /api/admin/suggestions/{id}/review`（reviewed + note，全盘镜像 feedback 的 review 动作）。bad_case 语义不适用建议通道。不做匿名提交、不做管理端通知红点。候选端入口：CandidateShell「意见反馈」页（模块二 §9.3 导航壳）；管理端 UI：TestCenter 反馈区「异议反馈 / 意见反馈」切换。

## 2. 评测契约

### 2.1 一致性测试（b）

- 固定 transcript 复跑，断言 **score_final 分差 ≤ 1**；
- 固定条件：model/provider/版本、temperature=0、rubric 与模型快照、（若适用）随机种子；
- score_live 属过程值，不在断言范围。

### 2.2 虚拟考生测试（c）

- 强/中/弱三档脚本端到端；
- 断言：总分排序（强 > 中 > 弱）**+ 短板定位符合预设 + required 覆盖 + 拒答/缺失状态 + 证据引用 + 报告状态**——短板断言已接入（`assert_weakness_identified`，报告生成纳入链路复用五子项结构断言；短板定位依赖 SSOT §21「短板=gap>0」约定，06-013 反转已同步）。

### 2.3 自动 bad case 候选

```
score_live 与 score_final 可比 且 |live − final| ≥ 阈值
（BAD_CASE_DIVERGENCE_THRESHOLD = 2，2026-09-06 裁决，config.py）
→ 创建 bad_case_candidate（排除：题目无效 / 模型不确定 / 系统错误 / 状态不可比）
→ 管理员审核确认，不自动改分（永不 UPDATE question_score 的 score 字段）
```

幂等：同 (session_id, item_id, question_id) 已有 pending 候选则跳过（报告版本化重复生成不重复建）。

### 2.4 数据隔离

- **eval 已使用独立临时数据库**（业务库只读快照 → gsd-eval- 临时库，结果经业务库连接写回 eval_results；后台任务异常落 failed 显式可见）；
- eval 运行留 eval_results；runs 参数需边界校验（当前 `runs: int = 3` 无显式上限钳制，**留待加固**）。

### 2.5 黄金集（a）

本期推迟（真实数据收集后另行排期），不作为本期验收项。

### 2.6 测试中心评测运行治理（2026-09-09 新增，SSOT §23）

- **测试中心评测运行（管理端，P8）**：触发一致性（b）/虚拟考生（c）测试并轮询结果（`eval_results` 承载，隔离临时库执行、业务库零写入）；
- **虚拟考生岗位下拉口径（banked 过滤）**：`GET /admin/positions/options` 增 `banked` 过滤参数（与 `status` 可组合）——仅列 `status='active'` 且该岗位存在 `status='active'` 题库行的岗位（已落库且使用中），测试中心下拉传 `status=active&banked=1`（原可选中 pending_review/inactive/无 confirmed 模型/题库未落库岗位，任务启动即失败入历史）；
- **运行历史删除（2026-09-09 增）**：`DELETE /api/admin/eval/results/{task_id}` 单条 + `POST /api/admin/eval/results/batch-delete`（body `{"task_ids":[...]}`，单事务）——仅终态（completed/failed）可删，running 行 409，批量含任一 running 整体 409 不删、unknown id 404；前端历史区终态行勾选 + 全选 + 单行删除/删除所选（确认弹窗，运行中行禁选）；eval_results 删行即彻底清理（评测写本落隔离临时库，业务库仅结果行）。

## 4. trace 与审计

- trace_link 关联角色：input / output / caused_by / scored / reported / source；唯一约束 (trace_id, entity_type, entity_id, link_role)；
- 旧 trace 的自由文本 ref_id 已在迁移时导入 trace_link（按 call_type 逐候选实体表探测，命中即拆 entity_type/entity_id 导为 link_role='source'，幂等 INSERT OR IGNORE；命不中保留原值不拆——弱关联不强造）；
- 管理员查看 trace 全文（含 prompt/response、候选人原文）须留 `REVIEW_ACCESSED` 访问审计；
- trace 演示期全量保留、不做脱敏（2026-09-06 裁决：利于验收审计；生产 PII 治理随真实上线再开——SSOT §31-5）。

### 4.1 异议详情与管理端定位（2026-09-09 新增，SSOT §22.2）

- **列表补列**：`GET /api/admin/feedback/list` 增「提交人」列 `username`（LEFT JOIN user；存量行 user_id NULL 保留、前端显示 —，行不消失）；
- **详情端点**：`GET /api/admin/feedback/{feedback_id}`（admin-only）——返回 `feedback_text`（全文）/ `status` / `created_at` / `username`（提交人）/ `review_note` / `reviewed_at` / `report_id` / `item_id` / `session_id` / `std_name` / `category` / `total_score`（回溯锚点齐备）；unknown id 404；
- **管理端定位（页内嵌入，2026-09-09 交互修正）**：反馈列表行「详情」→ 管理端测试中心**原地打开页内覆盖式报告视图**（不离开 `/admin/test-center`、不切换到候选端壳），报告整页在覆盖层内按候选人风格渲染（candidate 作用域样式，明暗主题沿用），异议横幅 + 能力项明细被异议行与逐题回顾同 item 题目双高亮 + 自动滚动定位明细行 + 命中逐题回顾自动展开。关闭两路：覆盖层「✕ 返回列表」或浏览器后退，均回到反馈列表**原地**（测试中心页 keep-alive，tab/子页签/状态筛选/列表滚动保留）；URL 以同路由 query `?feedback_id={id}` 记忆，刷新/分享经 detail 端点回溯 session_id 后照常恢复嵌入视图；
- **报告路由深链保留**：`/assessment/report/{session_id}?feedback_id={id}` 可直接访问，报告页检测该 query 拉详情；**候选端访问同 URL 静默降级**（详情端点 admin-only，403 不渲染横幅，页面其余正常）；详情 session 与 URL 不符亦不渲染（跨报告拼 query 双保险）；
- **异议详情覆盖层跟随测评快照（2026-09-09，SSOT §5/§22.2）**：覆盖层打开时按该场 session 读 localStorage 快照（`asmt-theme:<session_id>`，候选端 Chat/Report 进入与切换时写入）决定报告正文明暗（`.fbd-scope[data-theme]` 局部生效，不从 html 继承；无快照回落日间）；覆盖层管理壳跟管理员当前主题；
- 异议提交/review/bad_case 动作语义零改动（不改分、仅留痕）。无表结构迁移、无接口变更（本节两端点除外）。

## 1. 评分链（v2.0 最终确认）

```
原始回答证据 → 独立终局评分 score_final（P-score，temperature≈0，按 raw_hash 回捞原文）
→ item 内证据裁决 → 固定 item.weight 加权 → 画像报告
```

- **score_live 只用于过程性选题与难度导航，不参与最终分数**；与 score_final 的差值仅用于偏差分析与 bad case 候选，不写回分数；
- 客观题代码判分（answer_key 为空 = 题库缺陷，判题库无效而非满分）；**命中 = 5 分 / 未命中 = 1 分，与 §7 `(score−1)/4` 归一化同口径**；evidence_quote 取候选人回答前 60 字符（展示截断固定规则，非开放参数，`_OBJECTIVE_QUOTE_LEN`）；
- 终局评分失败且无可信结构化结果 → 报告 `FAILED`，不得生成 0 分正常报告；
- 报告生成**必须前置**终局评分：正常 UI 主链 score→report 由服务端串行链执行（D-08 方案 B：`POST /report` 内部先 score 后 report，前端无需显式调 `POST /score`；`/score` 端点保留为显式入口，completed 会话被服务层护栏拒绝 409）。

## 2. 拒答（REFUSED）

```
score_value = 0；score_state = REFUSED
```

- 0 是特殊状态值，**不是能力量表 1 分**；
- **拒答只进入行为聚合与完整度聚合，不进入能力等级聚合**：item 最终等级由有效能力证据决定，后续有效回答可以改变等级；
- 拒答事件永久保留，报告单独展示拒答次数与位置；
- 涉及受保护信息或合法隐私质疑的拒答 → 合规/人工处理，不直接记 0。

**实施注记（2026-09-06，SSOT §18）**：score_state 枚举位 `INSUFFICIENT_EVIDENCE / NOT_ADMINISTERED / INCOMPLETE` 本期**不产出**（by-design）：现终态由 REFUSED（拒答）、INVALIDATED（题库无效）与聚合层 IMPUTED/PROVISIONAL/NO_VALID_OBSERVATION + missing_warnings 语义等价覆盖；NOT_ADMINISTERED 的潜在场景（派发未答实例进 finalize）走 §5 缺失路径，不做区分。枚举位保留供校验与后续生产。

## 3. 分母规则

| score_state | 正常能力分母 | 缺失/警告 |
|---|---|---|
| SCORED | 进 | 否 |
| REFUSED | 不进（只进行为/完整度） | 单独记录 |
| INSUFFICIENT_EVIDENCE / NOT_ADMINISTERED / INVALIDATED / MODEL_UNCERTAIN / INCOMPLETE | 不进 | 是 |

系统错误与题目无效不得转成普通低分；全部无效观察 → `NO_VALID_OBSERVATION / HUMAN_REVIEW_REQUIRED`，不得补算出确定分。

## 4. item 内合并与综合题裁决

普通题与综合题先转统一测量记录再裁决：

```
item_measurement(question_id, item_id, observed_level, evidence_refs, measurement_source: ordinary|integrated)
item_final_level = adjudicate(ordinary_measurements + integrated_measurements)
```

- 普通最低测量资格先检查（综合题不能替代普通题第一次测量）；
- 按 rubric / 覆盖 / 稳定性 / 冲突裁决；**不按来源加权、不按题数重复乘 item.weight**；
- 共享 evidence span 只影响证据解释，不折扣、不自动复制评分；报告显式标记共享引用；
- **重大冲突取较低值，并留人工复核标记**；
- 综合题可作为最高等级证据来源（受其 rubric 约束）；
- 综合题整体 `ITEM_INVALID` → 所有绑定 item 综合结果无效、移出分母；单 item 证据不足不影响其他 item 独立评分（一题多 item 记录写入 question_score，`(question_id, item_id)` 合法）。

## 5. 缺失补算（普通非 gate item）

```
O = {score_state = SCORED 的 item 级测量}；M = 缺失集合
r = Σ(i∈O) w_i × s_i / Σ(i∈O) w_i，其中 s_i = (score_final − 1) / 4
缺失普通 item 补算值 = r，标记 IMPUTED
```

- `O = ∅` → 禁止补算（`NO_VALID_OBSERVATION / HUMAN_REVIEW_REQUIRED`，不得补算出确定分）；
- required 与 qualification 不适用比例补算；
- `IMPUTED` 参与总分与雷达，但必须特殊视觉标记，并展示真实观察数 / 缺失原因 / 观察覆盖率；
- **补算比例阈值已裁决 0.2**（`IMPUTE_RATIO_THRESHOLD`，2026-09-05 关口 A）：IMPUTED 覆盖率 > 2 成 → `PROVISIONAL + HUMAN_REVIEW_REQUIRED`（临时报告 + 人工复核）。

## 6. required 缺失与临时报告

```
report_status = PROVISIONAL；review_status = HUMAN_REVIEW_REQUIRED
```

- 不触发补测；
- **人工确认后可发布为正式报告，必须由管理员明确点击发布**，不自动发布；
- 报告必须列出：缺失 required item、缺失原因（拒答/系统错误/题目无效/模型不确定）、是否有补算、哪些结论未经人工确认。

## 7. 总分与门槛

```
总分 = Σ(item.weight × normalized_item_score) × 100
normalized_item_score = (actual_level − 1) / 4（1→0、5→1；与 §5 s_i=(score−1)/4 同尺度，
                         统一 observed/imputed 归一化——2026-09-05 关口 A 裁决，
                         作废旧实现 score/5 隐式口径）
gap = required_level − actual_level
门槛项（gate）：达标拿满 / 不达标 0，UI 红绿标签单列，不进 1–5 评分
```

大类 7:3 已体现在 item.weight 中，聚合**不再二次乘大类比例**。

## 8. 报告（五段式）

①总分读数条 + 门槛红绿标签表；②ECharts 雷达（required 灰 vs actual 蓝；**IMPUTED 特殊标记**）；③逐项明细表（gap 绿/红着色、行内理由、逐行「异议」按钮）；④优势/短板/建议三色卡（**代码排序**：优势 = gap≤0 中权重最大前 3（actual≥required，达标/超配）；短板 = gap>0 中 gap×weight 最大前 3（actual<required，低于要求）[SSOT §21，06-013 反转同步，2026-09-06]；LLM 只写自然语言且只能基于给定短板项）；⑤逐题回顾（score_final + 证据 quote + 来源定位，可溯回原文）。

### 8.1 报告状态机与发布校验

```
report_status: GENERATING → PROVISIONAL | READY → PUBLISHED | FAILED
review_status: NONE | REQUIRED | IN_PROGRESS | CONFIRMED | CLOSED
```

**发布前一致性校验（代码，七项）**：数字可从结构化评分重算；item.weight 总和一致；引用 question/message 属于该 session；model/version 与 session 快照一致；无效题/系统错误未进正常分母；IMPUTED/REFUSED/required 警告与结构化状态一致；文案无录用判断表述。

人工复核字段：`review_request_reason / reviewer_id / review_note / review_outcome / reviewed_at / publish_confirmed_by / published_at`。

**重复触发护栏（P0 成功标准 5，2026-09-06 补入 SSOT）**：`POST /sessions/{id}/report` 在会话已存在报告且报告处于 `GENERATING` 或终态成功（`PROVISIONAL`/`READY`/`PUBLISHED`）时返回 409（`REPORT_GENERATING` / `REPORT_ALREADY_GENERATED`），不重复触发评分/报告；报告为 `FAILED`（后台链失败）或无 report 行时允许重新入队（202），作为失败重试路径。

**流程（已落地）**：评分完成 → 聚合与七项校验 → 生成（PROVISIONAL 或 READY）→ 有人工复核要求则等待 → 管理员 `POST /reports/{report_id}/publish` 明确点击发布（携带 review_outcome/note）→ PUBLISHED。报告任务异常 → FAILED 行 + TASK_FAILED 事件显式可见（不静默）。报告表 version 列版本化（重复生成不再 DELETE 覆盖旧行）。

## 9. 异议与人工复核

- 候选人逐分异议 → feedback 表，**不自动改分、不触发报告重算**，只进人工处理与质量数据；
- 人工复核可查看证据、覆盖结果并决定报告是否发布；不修改原始评分（原始结果与人工结论以 override/复核记录叠加，不擦写）；
- 人工覆盖 gate 或认定题库/模型失效 → **二次人工确认**，必要时废弃当前测量另行安排；
- 管理员查看候选人原文/trace 需留访问审计事件（REVIEW_ACCESSED）。

## 模块一：JD 解析与胜任力模型构建（已实现）

> 本部分为《模块一实施设计（历史档案）》（原 05）v1.0 已实现内容的档案化摘录；实施期细节以该文档原文为准。

### 5.1 流水线（六工位，已实现）

```
①接入(粘贴/JSONL) → ②清洗(纯规则) → ③抽取(LLM#1) → ④归一消歧(词典+LLM#2)
→ ⑤聚合(代码频次+LLM#3裁决+代码算权重) → ⑥人审(P3审核页，确认升版本)
```

- 状态机：`imported → parsing → parsed/failed → aggregating → draft/stalled → confirmed`；confirmed 后新增 JD/重解析走 diff 审阅流升 v{n+1}；
- 归岗：job_title 规范化 → position 精确匹配 → 别名表 → 未命中建 pending_review 岗位（人工审激活）；
- 聚合：双比率（r/req）→ importance 阈值映射 → level 冲突交 LLM#3（无自动取众数）→ 权重代码计算；
- 三次 LLM 调用职责契约与提示词已定稿（见总文档附录 A），全部落 llm_trace。

### 5.2 权重口径（U3 锁定，模块三直接复用）

```
第一层（类目间）：硬技能 : 软技能 : 经验 : 门槛 = 5.5 : 2 : 2 : 0.5  → 55% / 20% / 20% / 5%
第二层（类内）  ：类目份额按各项 importance 系数分摊（required 1.0 / preferred 0.6 / plus 0.3）
                ↓ 合成结果（已算好，存 competency_item.weight，Σ=1）
```

**模块三算总分 = 直接复用 item.weight，不再二次乘 5.5:2:2:0.5。**

### 5.3 关键设计原则（已实现）

- 门槛项 `gate=true`（qualification 全部 + experience 年限项）二值判定，不进 1~5 级评分；
- 分数是历史事实，confirmed 模型不被静默覆盖（人工唯一权威）；
- 每道工序中间产物（raw_items/std_items/cleaned_text）落 jd_record 可查。

## §11.2 判据（next_difficulty 纯函数——逐条，事件类型映射）
- easy→medium：一次充分证据（sufficient_in_row ≥ 1）→ DIFFICULTY_RAISED
- medium→hard：充分且稳定（sufficient_in_row ≥ 1 且 stable_evidence）+ 仅 required_level > 4 的 item → DIFFICULTY_RAISED
- 降级（当前非 easy 才可降；仅统计有效候选人证据失败）：
  fail_same_difficulty ≥ 2（同 item 同难度连续两道有效题未达最低锚点）或 followup_ambiguous=True
  → DIFFICULTY_LOWERED
- 恢复（降级后滞回）：连续两次充分（sufficient_in_row ≥ 2）或一次稳定（stable_ever）→ DIFFICULTY_RESTORED
- 跳级禁止：任何跨档迁移（easy→hard）不可产生；无合法迁移 → ("PATH_UNAVAILABLE", None) 标记事件不静默
- 一次实例内不升降级：本函数只在实例封存后调用；返回的 new_difficulty 由【下一实例】承载（current_difficulty 写进 snapshot，选题层读取）
- 输入封装：is_valid_failure=False 的一律不累计 fail（七类排除——由调用方从 02-04 observation 结果传入）

## 「不计入普通失败」七类（§11.2 原文清单）
技术故障 TECHNICAL_OR_ACCESS_BARRIER / 无障碍（同前）/ 题目无效 ITEM_INVALID / 模型不确定 MODEL_UNCERTAIN /
合理流程质疑 PROCESS_CHALLENGE / 明确拒答 DECLINED / 攻击性事件 CONDUCT_EVENT——
调用方（assessment.py 封存点）从 02-04 落库的 answer_state/observation 结果判断 is_valid_failure，
七类一概 False（不触发降级计数）。

## 事件 payload 判据摘要（Pitfall 5——必带，测试断言内容不只断言 event_type）
{"criterion": "followup_still_ambiguous" 或 "two_consecutive_below_anchor" 或
 "one_sufficient_observation" 或 "sufficient_and_stable" 或 "hysteresis_two_sufficient" 等,
 "evidence_counts": {"sufficient": 0, "insufficient": 2},
 "from_difficulty": "medium", "to_difficulty": "easy"}
事件行 from_state=旧难度 to_state=新难度（迁移事件必填——§13.1）。

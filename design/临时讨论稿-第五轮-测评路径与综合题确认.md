## 1. 本轮确认结果

本轮对第四轮第 6 节的 7 个问题全部确认：

1. `integrated question` 是独立测量阶段/题型，不是普通难度的第四级；
2. 一个能力项的 `easy → medium → hard` 如果每一级对应不同题面，则每个实际呈现的题面都视为一个新的普通主问题实例；
3. 综合题对某个能力项同时具备独立 `measurement_target`、独立证据和独立评分状态时，可以计为该能力项的一次 `item_minimum_valid_measurement`；
4. 普通能力项至少需要一次普通题测量，综合题可以补充，但不能替代这次最低普通测量；
5. 综合题阶段在普通 hard/soft 计划完成或合法封存后进入；
6. 题量拆分为 `ordinary_plan_count`、`ordinary_exception_count`、`integrated_plan_count` 分别记录；
7. 不同题面创建新的 `assessment_question` 实例；`followup` 保持在同一实例的子轮次内。

## 2. 正式测评路径

### 2.1 普通能力项路径

```text
选择一个普通 hard/soft 能力项
  ↓
激活 easy 题面
  ↓
候选人首次回答
  ↓
必要时在同一 assessment_question 内 followup-1 / followup-2
  ↓
封存当前题实例
  ↓
根据证据和状态决定：
  ├─ 进入 medium：创建新的 assessment_question 实例
  ├─ 进入其他 item：创建新的 assessment_question 实例
  ├─ 降级/保持：按策略创建对应题面实例或结束该 item
  └─ 进入人工/不完整状态
  ↓
medium
  ↓
根据证据和状态决定是否进入 hard
  ↓
hard
  ↓
普通 hard/soft 计划完成或合法封存
  ↓
进入独立综合题阶段
```

### 2.2 实例层级

```text
assessment_question（普通主问题实例）
├── assessment_message（候选人首次回答）
├── assessment_message（assistant 追问）
├── assessment_message（候选人追问回答）
└── assessment_message（assistant 收束/过渡）
```

其中：

- 每个不同题面只创建一个新的 `assessment_question` 实例；
- 追问不创建新实例；
- 同一能力项的 easy、medium、hard 若展示不同题面，分别拥有不同实例；
- `session × item` 的导航状态另行记录当前难度、已达难度、证据覆盖和路径变化；
- 一个实例结束后才能进入下一个普通主问题实例。

## 3. 综合题规则

### 3.1 独立阶段

综合题不属于普通 hard/soft 主问题配额，拥有独立槽位：

```text
ordinary_plan_count
+ ordinary_exception_count
+ integrated_plan_count
```

综合题在普通 hard/soft 计划完成或合法封存后进入。普通阶段不能因为存在综合题而跳过尚未覆盖的普通 required 能力。

### 3.2 数量上限

```text
0 ≤ integrated_question_count ≤ 2
```

实际激活数量由岗位级策略配置和当前综合覆盖状态决定，不由 LLM 自由增加。

### 3.3 多能力绑定

综合题允许绑定多个能力项，但每个绑定项必须单独配置：

```text
item_id
measurement_target
rubric_mapping
evidence_requirement
```

只有满足以下条件，综合题才计为该 item 的一次有效测量：

1. item 在综合题绑定列表中明确存在；
2. item 有独立 measurement target；
3. item 有独立 rubric 或明确评分映射；
4. 回答中能定位属于该 item 的独立证据；
5. 证据不是从其他 item 无依据复制；
6. item 能独立得到 `SCORED`、`REFUSED` 或 `INSUFFICIENT_EVIDENCE` 状态；
7. 综合题整体没有被标记为 `ITEM_INVALID`。

### 3.4 普通题最低测量不可被综合题替代

普通 hard/soft 能力项必须先获得至少一次普通题测量机会。综合题的有效证据只能：

- 补充该 item 的已有普通题证据；
- 增加证据稳定性或覆盖范围；
- 在报告中作为独立综合场景证据展示；
- 不能替代该 item 的第一次普通题测量。

如果普通题因系统错误、题目无效或模型无法判断而没有形成有效测量，综合题不能绕过该问题直接把 item 标记为已完成；应进入人工复核或不完整处理。

如果普通题完成了明确拒答流程，则该 item 已有普通测量事件，状态为 `REFUSED`，综合题是否仍需补充由策略决定，但不能覆盖或抹除拒答记录。

## 4. 题量记录规则

### 4.1 三类主问题数量

```text
ordinary_plan_count       = 普通题计划数量
ordinary_exception_count  = required 刚性例外新增普通题数量
integrated_plan_count     = 综合题独立槽位计划数量
```

实际数量：

```text
ordinary_actual_count = ordinary_plan_count + ordinary_exception_count
integrated_actual_count ≤ min(integrated_plan_count, 2)
```

### 4.2 Followup 不计入主问题数量

```text
main_question_count
  = ordinary_actual_count + integrated_actual_count

followup_count
  = 独立统计的过程轮次
```

`followup_count` 用于：

- 单题追问上限校验；
- 测评过程审计；
- 模型行为分析；
- 后续成本和体验分析；

但不计入主问题数量，也不占综合题槽位。

## 5. 当前不应再使用的表述

为避免后续再次混淆，删除或避免使用：

- “难度递进题是否占基础配额”；
- “综合题是难度第四级”；
- “followup 是新题”；
- “综合题绑定能力就等于能力已测量”；
- “题目被展示就等于获得有效测量”；
- “required 例外、难度递进、综合题是同一种额外题量”。

统一使用：

- `difficulty_path`：普通能力项的 `easy → medium → hard` 路径；
- `assessment_question`：一次实际呈现的主问题实例；
- `followup`：当前实例内部的补证据子轮次；
- `integrated_question`：独立综合测量阶段/题型；
- `item_minimum_valid_measurement`：某 item 一次有效、可归因、可追溯的测量；
- `required_quota_exception`：required 未覆盖时新增的普通主问题机会。

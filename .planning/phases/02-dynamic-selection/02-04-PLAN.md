## InterviewObservation / ObservationDims（D-22——schemas.py 惯例照 ExtractItem 先例）
ANSWER_STATES = Literal["VALID_EVIDENCE","NEED_CLARIFICATION","OFF_TOPIC","NO_RECALL","DECLINED",
                        "PROCESS_CHALLENGE","CONDUCT_EVENT","TECHNICAL_OR_ACCESS_BARRIER",
                        "PROMPT_INJECTION","MODEL_UNCERTAIN","ITEM_INVALID"]  # §11.4 11 态
class ObservationDims(BaseModel):
    relevance: bool = Field(description="与测量目标相关")
    specificity: int = Field(ge=0, le=3)
    attribution: bool = Field(description="有可归因事实（项目/数据/角色）")
    required_points_covered: Optional[bool] = None
    source_span_available: Optional[bool] = None
    contradiction_detected: Optional[bool] = None
    uncertainty: Optional[bool] = None
class InterviewObservation(BaseModel):
    answer_state: ANSWER_STATES
    observation: ObservationDims
    reply_suggestion: Optional[str] = None    # 可选话术建议，裁决层可弃用
    reason: str = ""

## 裁决层纯函数（新——Simplicity 边界）
classify_observation(obs: InterviewObservation) -> tuple[bool, dict]:
  返回 (evidence_sufficient, detail)——§11.3 排除清单代码化：
  evidence_sufficient = (answer_state == VALID_EVIDENCE
      且 relevance=True 且 attribution=True 且 specificity ≥ 1
      且 contradiction_detected 不为 True 且 uncertainty 不为 True)
  （required_points_covered/source_span_available 属 Phase 5 证据链强化——Phase 2 不必真值，
    维度照 schema 保留，裁决不消费这两个键）
stable_evidence 轻量版（A2 决议）：is_stable_evidence(conn 上下文由调用方聚合，snap 的 sufficient_in_row)——
  判据 = sufficient_in_row ≥ 2（两个不同实例充分观察）。Phase 2 只做难度导航用的轻量版（Phase 5 rubric 一致性/矛盾裁决留白）。

## 裁决规则（action 决定——代码唯一权威）
1. answer_state == DECLINED 且该实例未确认过 → action='confirm'（新 action 值——控制类一次性确认话术，
   reply 用固定 SUPPORT 文案如"可以不回答这道题吗？跳过后将不再回到该题"——§11.4 拒答处理原则）
2. answer_state == DECLINED 且已确认过（同实例第二次 DECLINED）→ action='seal_refused'（内部值；
   submit_answer 消费它走封存 + REFUSED 路径——由 assessment.py 分支处理；返回 dict 的 action 键仍写 'next'
   并带 refused 标记键 refused=True，避免前端 sse.js 对未知 action 值处理破裂——只加不减原则的最小侵入）
   （实现取舍记 SUMMARY：API 层认 refused 标记键封存当前题并跳下一题）
3. answer_state == MODEL_UNCERTAIN 或 Pydantic 校验失败 → 不猜测：action 按证据充分性 False 处理（NEED-model-uncertain
   降级路径——下一 action 不 followup 直接 next（不卡死会话，§11.5；人工通道完整化属 Phase 3 错误处理）
4. evidence_sufficient=False 且 answer_state == NEED_CLARIFICATION → followup（受 ≤2 上限）
5. evidence_sufficient=True → next（或 finish 由规则触发——02-02 已落"池耗尽即 finish"）
6. OFF_TOPIC/NO_RECALL → followup（重定向/格式脚手架——§11.4 原则映射，受 ≤2 限制后转 next）
7. PROCESS_CHALLENGE/CONDUCT_EVENT/TECHNICAL_OR_ACCESS_BARRIER/PROMPT_INJECTION/ITEM_INVALID
   → 各自处理原则的最小实现：不扣分不猜疑 → next 推进 + 事件留痕（PROMPT_INJECTION 的 INJECTION_DETECTED 事件留 Phase 3 REF-6.4，
   本期不写该事件——CONTEXT 事件最小集；answer_state 已落 OBSERVATION_CLASSIFIED payload 即审计足够）

## score_state 6 态（D-28 / Pitfall 7）
Phase 2 生产三态：SCORED（正常评分）/ REFUSED（拒答封存）/ INVALIDATED（answer_key 空的客观题）。
枚举位预留不生产：INSUFFICIENT_EVIDENCE / NOT_ADMINISTERED / INCOMPLETE /（IMPUTED、
HUMAN_REVIEW_REQUIRED、MODEL_UNCERTAIN 属 Phase 5——CONTEXT D-28 字面六态为 Phase 2 的口径集合）。
Q1 决议：INSUFFICIENT_EVIDENCE 保持代码枚举常量存在（供 Phase 5 生产与 02-05 测试引用枚举完整性），但本 phase
score_session 不写它。模块级常量 SCORE_STATES = ("SCORED","REFUSED","INSUFFICIENT_EVIDENCE","NOT_ADMINISTERED","INVALIDATED","INCOMPLETE")（N11 代码校验惯例参照 _VALID_ACTOR_TYPES）。

## §12.4 分母规则（落 aggregation）
SCORED → 进正常观察（existing actual 计算路径）
REFUSED → 不进能力等级分母；只进行为/完整度聚合 → aggregate 返回 dict 增加 "refusals": [{"item_id", "std_name", "question_id"}] 列表
INVALIDATED / INCOMPLETE（枚举位）→ 排除 + 缺失警告列表（返回 dict 已有键基础上增加
"missing_warnings": [{"item_id", "std_name", "reason"}]）——不隐式转 0，不静默
INSUFFICIENT_EVIDENCE / NOT_ADMINISTERED → 同排除路径（Phase 2 无生产者，过滤条件一并涵盖——前向兼容 Phase 5）
注：IMPUTED/HUMAN_REVIEW_REQUIRED 不在 Phase 2 过滤名单（Phase 5 生产时再收——过度过滤会与 Phase 5 冲突）。
聚合口径（Pitfall 7 收敛）：SQL WHERE score_state IN ('SCORED') 取能力分母；REFUSED 单独 SELECT 列表化；
INVALIDATED 等排除态单独 SELECT 进 missing_warnings。

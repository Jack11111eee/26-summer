# 临时讨论稿：资格核验表单 facet 化（gate 表单 v2）

**日期**：2026-09-08　**状态**：设计收敛完成（含上游增量治理，第二轮），SSOT §16.1 + §8/§9 修订稿待授权　**范围**：模块二 §16.1 表单链 + 模块一聚合产物
**触发**：实测评发现资格核验表单下拉框无选项（P0 bug，已修，见 §8），暴露更深层问题——gate qualification items 未归一，候选人被迫对同质事实面逐条作答。第二轮讨论（同日）将治理边界上移至聚合产物层。

---

## 1. 问题

全库 gate=1 的 qualification std_name 约 150 个，同一事实面（最高学历 / 院校档次 / 英语等级 / 专业范围 / 年龄 / 出勤天数……）存在大量近重复措辞。典型实测评场景：候选人同场需逐一回答「本科及以上学历」「硕士及以上学历」「211硕士及以上学历」「计算机相关专业」「相关专业」「相关专业背景」「机器视觉/数学/电子计算机等相关专业」——实为 3 个事实面（学历、院校档次、专业范围）。且当前实现将每个 qualification item 渲染为该 item 专属的二值下拉（是/否），信息密度与体验双差。

另一个语义粗糙点：所有 experience 年限项共用同一个「工作年限（年）」数字（`server/services/forms.py` base 字段；`_gate_check` 消费），即「SLAM 融合开发经验 ≥ 5 年」拿候选人**总工作年限**判定。

冗余的**根在上游**：模型 items 本身未归一（「相关专业」与「相关专业背景」来自不同 JD）。词典治理第 3 层（126 名身份迁移组）冻结待逐条裁决，这批 qualification 近重复大概率混在其中。本方案定位为**下游兜住**，不抢上游治理的位置。

## 2. 用户裁决（2026-09-08）

**第一轮（五条）**：
1. **收集形态**：紧凑结构化表单（非对话式 + 抽取）。对话式收集（P-form-facts，§16.2 简历链同构）留作后续阶段复用同一 facet 事实模型，不在本期范围。
2. **专业范围类**：不做 LLM / 文本解析，渲染为**勾选组**——一次读完所有专业相关断言，勾选符合项。
3. **长尾 fallback**：规则分类不出的 qualification item，原样降级为勾选组陈述（最坏情况 = 现行为换更好的控件，永不 block）。
4. **experience 标签**：改为「与岗位相关的工作年限（年）」，只改文案，不拆分、不动模型。
5. **P0 bug**（下拉空白）：允许单独先修——已完成（见 §8）。

**第二轮（四条，上游增量治理）**：
6. **A 类自动合并**（有序 facet 断言等价 → 聚合时合并一行）：同意实施。
7. **打标前移**（facet 分类从渲染时挪到 item 生成时，competency_item 增 facet_key + facet_params_json 两 nullable 列）：同意实施。
8. **B 类**（专业范围措辞漂移，跨 JD 近重复）：**缓**——facet 勾选组已消除候选人侧痛点，管理端清洁度是低频收益，不动词典第 3 层冻结裁决。
9. **报告 gate 段按 facet 折叠**：随 v2 一起做。表单分段控件（segmented）与提交摘要两个备选项**砍掉**，保最小改动面。

## 2.1 三层问题解剖（第二轮讨论的框架基础）

「同一事实面不同措辞」不是一层问题，分三层各有正确疗法：

| 层 | 实例 | 定性 | 归属 |
|---|---|---|---|
| 第 1 层·词面（std_name 近重复） | 「相关专业」vs「相关专业背景」 | 不同 JD 写法漂移，宽窄语义存疑 | 词典治理第 3 层（冻结中，本方案不动） |
| 第 2 层·断言（同命题不同措辞） | 「本科及以上学历」vs「全日制本科学历及以上」 | 有序轴上阈值等价，**可确定性自动合并** | 本方案 A 类合并（聚合产物层） |
| 第 3 层·事实面（一次可答的事实） | 本科/硕士/211硕士 都是「最高学历」轴上的阈值 | 一个下拉框承载 | facet v2 渲染层（第一轮已授权） |

候选人均值：每模型 12.1 个 qualification gate 项（最高 61）。rift 生成机制：LLM#2 消歧只在单 JD 内做（`pipeline.py:disambiguate_items` 按 jd_id 逐个跑），跨 JD 近重复在聚合时相遇而 `_collect_items` 按 `(std_name, category)` 精确分组——措辞不同即分组不同。**A 类合并施加在第 2 层，第 1 层不动（词典治理第 3 层冻结裁决有效）。**

## 3. 方案：facet 归并 + 确定性派生

### 3.1 facet 模型

facet 分类在**聚合落 item 行时**执行（打标前移，第二轮裁决 7），渲染时只读已打标结果：

```
_run_aggregate 写 item 行时：classify(std_name, category) → facet_key + 派生参数
                              → competency_item.facet_key / facet_params_json
渲染时（forms.py）：按 facet_key 分组渲染，不再跑分类器
报告时：gate 段按 facet_key 折叠展示（裁决 9）
```

存量模型 facet_key 为 NULL → 渲染时整组走勾选组 fallback（保守），或该岗位重聚合刷版本后自然带上。gate qualification items 按**确定性规则**（关键词词表 + 内嵌数字解析，纯函数、无 LLM）归并为少量候选事实面（facet），每个 facet 一个收集控件：

| facet | 控件 | 答案形态 | 派生规则 |
|---|---|---|---|
| `education_degree` 最高学历 | 有序枚举（专科/本科/硕士/博士） | 单选 | item 阈值 ≤ 候选人学历 → 通过；学历类断言取措辞中出现的**最低学历档**为阈值（宽读法，如「学士或硕士学位」→ 本科） |
| `school_tier` 院校档次 | 有序枚举（985/211/其他） | 单选 | 候选档 ≥ item 要求档 → 通过（985 ⊆ 211，985 毕业生满足 211 要求） |
| `english_level` 英语等级 | 有序枚举（六级/四级/无） | 单选 | 同上，等级比较 |
| `number_range` 数值断言 | 数字输入 | 数值 | std_name 内嵌数字解析出阈值与量纲（如「年龄30岁以上」→ 阈值 30 岁），数值比较；解析不出 → 降级 fallback 勾选组 |
| 专业组 + 二值断言 + 长尾 fallback | **勾选组**（勾 = 是） | 0..n 勾选 | 勾选项 = 该 item 真；未勾 = 否（`_gate_check` 现有「是」真值表直接命中） |

`years_of_experience`（base 字段）保持独立数字输入，标签改为「与岗位相关的工作年限（年）」，`_gate_check` 消费逻辑不变。

### 3.1.1 A 类自动合并（聚合内，断言等价合一）

`_collect_items` 分组后、LLM#3 分档前，对 gate qualification items 增加**断言等价合并**：

- **合并谓词**：同 `facet_key`（限有序 facet：education_degree / school_tier / english_level / number_range）且派生参数完全一致（如都推导为 `degree ≥ 本科`）。复合断言（如「211硕士及以上学历」横跨学历+院校两轴）不参与自动合并，走 fallback。
- **合并行为**：合并为一行 item（std_name 取更高频或更具体者——词表里含更窄词义优先；evidences/jds/req_jds 并集；occurrence 合并）。合并发生在分层聚合之前，即被合并项从 LLM#3 视野中消失，从根上省掉同断言多行产物。
- **不参与**：专业组（major_group）、长尾 fallback、全部 experience 项、任意非 gate 项——B 类近重复一律不合并（裁决 8：缓）。

降幅实测口径（SLAM v5 确认模型）：7 项 → 4 控件为 facet 渲染效果；A 类合并的降幅需实施前用分类器全库跑一遍量化（「本科及以上」vs「全日制本科及以上」类真重复的实际数量）。

**渲染效果对比**（本实测评场景）：7 个二值下拉 → 「最高学历」+「院校档次」两个枚举 + 「专业/资格项」一个勾选组（四条专业断言并列勾选）+ 原有工作年限，共 4 项。

### 3.2 派生管线（插入点固定）

```
facet 答案（候选人提交）
  → validate_and_submit 的必填/枚举/长度校验
  → 【新增】facet 派生：展开为逐 item 真值 {std_name: true/数值}（纯函数）
  → 现有 _gate_check 真值表消费（True/"true" 已在真值表内，零改动）
  → gate 行写入 / GATE_EVALUATED（不变）
```

- 直接映射项（勾选组）：payload 即逐 item 真值。
- 派生项（学历链 / 档次链 / 英语链 / 数值断言）：派生结果为 `true/false`，命中 `_gate_check` 现有真值表（`True`, `"true"`, `"是"` 等）。
- 分类的确定性规则随快照落库（见 3.3），**同一次测评内规则与渲染时的快照一致**，不因代码后续演进而漂移。

### 3.3 快照 v2 与 v1 兼容

- `schema_version`: v1 → **v2**。v2 快照 fields 每字段增 `facet` 键；宿主 item 的派生参数（阈值、档位）随快照落库。
- **v1 兼容**：已 open 的 v1 rendered 实例走旧链完投（v1 payload 本就是逐 item 二值，`_gate_check` 原样消费），不迁移、不转换、**不因升级重渲染**（快照不可变语义）。
- form_instance 表结构不变（快照自版本化，无需 ALTER）。
- 渲染白名单 `_FIELD_WHITELIST_KEYS` 需增 `facet` 键（GET /forms/{id} 响应同步）。

### 3.4 payload 两段式

payload_json 建议存两段：**收集到的 facet 原始答案**（如 `education_degree: "硕士"`、勾选列表）+ **派生结果**（逐 item 真值）。两段均落库，审计可复现：从 facet 答案 + 快照内派生参数可复现每个 item 的 gate 判定。具体键名实施时定，不进 SSOT。

## 4. 不变量（本次改动的收口边界）

- **派生层插入点固定**：`validate_and_submit` 枚举校验之后、`_gate_check` 之前；派生函数纯函数、无 LLM、无新表。
- **不动**：gate 行结构（`question_score`）、aggregation 对 gate 结果的消费、`_gate_check` 本体与真值表、form_instance 表结构。
- **A 类合并改动面**：`_collect_items` 输出后的一次纯函数变换（分组键从 `(std_name, category)` 扩展为有序 facet 的 `(facet_key, 派生参数)`）；LLM#3 prompt、分档逻辑、权重计算、report/aggregation 下游全部不动。competency_item 增两 nullable 列（facet_key / facet_params_json），无表结构破坏。
- **报告侧**：gate 段按 facet 折叠展示（裁决 9）——同一 facet 的多个 item 折叠为一行（如「学历：硕士达标（本科及以上 ✓ / 硕士及以上 ✓ / 211硕士及以上 ✗）」），消费 question_score 的 gate 行照读，仅展示层分组。
- **表单体验备选项裁决**：分段控件（segmented）、提交摘要回显——砍掉，保最小改动面。
- schema 快照不可变语义、幂等/revision 生命周期全部沿用。

## 6. 测试口径

- **聚合层（A 类合并 + 打标）**：facet 分类正确性（学历链/档次链/英语链/数值/专业组/长尾六类各覆盖）；断言等价合并（「本科及以上学历」+「全日制本科学历及以上」→ 一行）；不合并面（复合断言、专业类、跨词面近重复如「相关专业」vs「相关专业背景」仍两行）；存量模型 NULL 打标降级渲染。

### 9.2 关键取舍（词表 v1 内容与边界裁决）

1. **复合断言归勾选组（G16 与 B2 冲突的收口）**：7 std_name 的 SLAM 场景实测渲染 **3 个 facet 控件**（年限 number + 学历 select + 勾选组），而非讨论稿 §3.1.1 概念图的「4 控件（含档次 select）」——「211硕士及以上学历」按 B2 已裁决行为（复合断言 → classify 返回 None → 勾选组）。概念图的 4 控件预期隐含「复合断言拆两枚举共同承载」设计，与 B2 显式规则矛盾；按 SSOT §16.1「专业范围类与**未分类长尾项**合并为勾选组」（复合断言不在有序 facet 分类内）与 B2 裁决实施。
2. **学历语境词门槛**：`_DEGREE_CTX`（学历/学位/毕业）——「硕士及以上」「博士」等裸学历词**不分类**（降级勾选组），防「硕士薪资面议」类误伤。已知副作用：部分真学历断言因措辞无语境词落勾选组（保守方向，勾选组永不 block，可后续词表 iterate）。
3. **英语能力词**（口语/听力/写作/阅读/翻译/交流）命中时整体 → None（勾选组），即使同句含等级词（「英语口语流利（六级）」不做成等级单选）——开放点 3 定稿。
4. **中文数字不解析**：「年龄三十岁以上」→ None → 勾选组（v1 只做阿拉伯数字 + metric 词表，宁缺勿错）。
5. **number metric 词表 v1**：仅 age（年龄/周岁/岁）与 weekly_days（出勤/每周/周）两个 metric；「5年以上」无 metric 词 → None（experience 由 base 字段承载，本就不该进分类器）。新 metric 走词表追加，不改结构。
6. **v2 判据用形态自查**：`fields 带 facet 键或 checklist 控件`（不依赖 schema_version 列——直插行/修订行可能不带）；纯 base 字段（无 qualification gate item）的快照走 v1 行为（无 facet 答案可派生，两路径等价）。
7. **A 类合并 std_name 取舍**：同参数组内取**词更长**者为保留措辞（「全日制本科学历及以上」>「本科及以上学历」）——更窄措辞承载更多语义；与「更高频」启发式相比可解释且无需频次依赖。
8. **checklist 提交形态**：`payload["checked"] = [std_name, ...]`（数组）；`_validate_payload` 对数组成员做枚举校验（`FORM_INVALID_OPTION`），整组 required=False（开放点 4）。

## §10.6 四层选题（D-17——顺序严格，不可调换）
①合法性过滤：题库 status='active' 且 category IN ('hard_skill','soft_skill')（experience/qualification 剔除）
  且 scope 口径（general 或 position=本岗位）且 question_id 未被本会话已建实例使用
  且 model_id 匹配——Phase 4 前用 position 归属近似（题库行 model_id 为 NULL 的现状全放行，见下"版本近似"）
②required 硬约束：模型中未覆盖（本会话尚无该 item_id 实例）的 required item 优先；
  普通计划（N 题）耗尽后仍有未覆盖 required → 走例外补选分支（见下）
③配额：7:3 大类（largest_remainder_73）+ tier（tier_targets， ceil 0.8/0.6/1.7 公式）——已实例计数实时扣减剩余
④排序三键（"题目质量"显式禁用——D-17/§31 红线，三键已确定性可审计）：
  chain 后继（当前实例 chain_key 相同且 chain_seq=当前+1 的题优先，可让位 required）
  → item.weight 降序（题库行经 item_id 关联 competency_item.weight；NULL 视作 0）
  → 稳定随机种子（seed = int(sha256(session_id).hexdigest()[:8], 16)，Q3 决议——selection_reason 记 seed 值）

## 纯函数规格（§10.2/§10.3，测试断言直接用）
largest_remainder_73(n) -> (hard, soft)：
  raw_hard, raw_soft = 0.70n, 0.30n；先取整；余下名额按小数大小分，相等归 hard
  样例（§10.2 表）：N=9→(6,3) N=10→(7,3) N=11→(8,3) N=15→(11,4)
tier_targets(category_quota, available_counts) -> {tier: target}：
  required_target = ceil(q*0.8/1.7)、preferred_target = ceil(q*0.6/1.7)、plus = q - req - pref
  边界 clamp：题量不足时先保 required 再保 preferred，plus 用剩余（soft 仅 2 题 → 1/1/0）
plan_quotas(n, categories_present: dict[category -> tier 可用量]) -> {category: {tier: target}}
  （层③每轮实时调用；已实例计数在外部扣减——readiness 第 5 步同源复用此公式做"题库量是否足够"预检）

## required 刚性例外（§10.5，D-19）
普通计划（N 题实例化完）后检查 uncovered required items（模型 importance='required' 且 gate=0 且本会话该 item_id 无已答实例）：
  每item最多一次例外（例外记录进 path_state_snapshot 或会话级判断即可——不建新表）；
  例外题只允许 medium（候选查询 category 匹配 + difficulty='medium' + 未用）；

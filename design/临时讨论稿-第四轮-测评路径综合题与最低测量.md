## 0. 本轮首先纠正一个概念混淆

上一轮将以下三件事混在了一起：

1. 普通题的难度递进；
2. required 能力未覆盖时的刚性配额例外；
3. 最终综合题。

本轮按用户澄清，三者必须分开。

### 0.1 正确的测评路径

用户指的难度/测评路径是：

```text
easy → medium → hard → integrated question（综合题）
```

但需要准确表述：

- `easy / medium / hard` 是普通题的难度层级；
- `integrated question` 是最后阶段的综合测量题型/测量阶段，不是普通难度的简单“第四级”；
- 综合题可以拥有自己的难度属性，但不能仅因为它位于最后阶段，就把它当作 `hard` 的上一级并自动使用同一难度规则；
- 是否进入下一个节点由代码状态机根据当前测评状态决定；
- `followup` 仍是当前题内追问，不是路径中的新节点。

推荐用两个正交字段表达：

```text
question_type: ordinary | integrated
ordinary_difficulty: easy | medium | hard | null
measurement_stage: ordinary | integrated_final
```

而不是把综合题直接编码成 `difficulty=integrated`。

### 0.2 三种机制的边界

#### 难度递进

```text
easy → medium → hard
```

含义：对同一能力项逐步提高题目挑战程度，以判断是否有足够证据支持更高能力等级。

#### required 刚性例外

含义：某个 required 能力项尚未获得有效测量机会时，即使所在大类或 tier 的基础配额已满，也允许额外激活一条合法题目，并记录 `required_quota_exception`。

它不是难度递进，也不是综合题。

#### 综合题

含义：普通能力题阶段完成或达到策略规定的最终阶段后，使用独立槽位进行跨能力联合测量。

综合题：

- 可以绑定多个能力项；
- 每个绑定项必须有独立 `measurement_target` 和证据拆分规则；
- 拥有独立题量槽位；
- 每次 session 最多两题；
- 不占普通 hard/soft 主问题基础配额；
- 不允许因为一题同时提到多个能力名，就自动认为多个能力都被测量。

# 1. 本轮已明确确认的结论

## 1.1 7:3 同时约束最终权重和普通主问题基础数量

本轮确认：

> `hard_skill : soft_skill = 7 : 3` 同时作为普通能力模型的最终 item 权重总比例，以及普通主问题的基础数量比例。

二者是两个不同层面的约束：

```text
最终权重层：
Σ hard item.weight = 0.70
Σ soft item.weight = 0.30

普通主问题资源层：
hard_base_quota : soft_base_quota ≈ 7 : 3
```

最终分数中不得再次把 hard 分乘 0.70、soft 分乘 0.30，否则会重复计算。

若普通主问题目标数量为 `N`，基础配额可表示为：

```text
hard_base_quota = integer_allocate(0.70 × N)
soft_base_quota = N - hard_base_quota
```

整数分配方法、`N` 的岗位级来源和 required 例外仍按第三轮待确认内容处理。

## 1.2 综合题拥有独立题量槽位

本轮确认：

```text
普通 hard/soft 主问题基础配额
+ integrated_question_slot
```

综合题不从 hard/soft 的 `N` 中扣除。

如果：

```text
N = 10
integrated_question_count = 1
```

则计划结构是：

```text
7 道 hard/soft 普通题
3 道 hard/soft 普通题
1 道综合题
```

综合题实际数量最多为两题，但默认应由岗位策略配置 `integrated_question_target` 决定，不能由 LLM 自由增加。

## 1.3 综合题默认最多两题

每次 session：

```text
0 ≤ integrated_question_count ≤ 2
```

是否激活第二题只能由代码策略依据：

- 第一题综合覆盖情况；
- 尚未覆盖的联合 measurement target；
- 是否存在合法的第二综合题；
- 当前 session 是否已经进入最终综合阶段；
- 题目版本和 rubric 是否匹配；

决定。不得由模型单独决定。

# 2. “最低测量机会”的重新定义

上一轮使用“最低测量机会”这一表述不够精确。本轮建议改为：

> **item_minimum_valid_measurement：某个评分能力项至少获得一次有效、可归因、可追溯的测量机会。**

这不是“题目被展示过一次”，也不是“题目文本提到过该能力”。

## 2.1 普通题满足最低有效测量的条件

一条普通题只有同时满足以下条件，才算该 item 的一次最低有效测量机会：

1. 题目属于当前岗位和已确认模型版本；
2. 题目明确绑定且只绑定一个主评分 `item_id`；
3. 题目实际激活到当前 session；
4. 候选人提交了可处理的回答，或完成了明确拒答流程；
5. 题目没有被标记为 `ITEM_INVALID`；
6. 没有因系统错误导致回答丢失或无法判断；
7. 题目和回答都能回溯到 session/question/message/trace；
8. 该题的状态已经封存为可评分、拒答或明确缺证据。

### 关于拒答

如果候选人明确拒答：

- 该题发生过一次测量机会；
- `score_value=0`；
- `score_state=REFUSED`；
- 该能力不应再被误报为“从未测量”；
- 但拒答事件必须在报告中单独展示。

如果是系统错误、题目无效或模型无法判断：

- 不算有效测量机会；
- 进入 `INCOMPLETE` 或 `HUMAN_REVIEW_REQUIRED`；
- 不自动映射成拒答或普通低分。

## 2.2 综合题满足某个 item 最低有效测量的条件

综合题可以绑定多个能力项，但只有对某个具体 item 同时满足以下条件时，才能算该 item 的一次最低有效测量机会：

1. 该 item 在综合题的绑定列表中明确存在；
2. 该 item 有独立的 `measurement_target`；
3. 该 item 有独立 rubric 或明确的综合题评分映射；
4. 评分器能从回答中定位属于该 item 的证据片段；
5. 该证据片段不是仅由其他 item 的证据复制而来；
6. 该 item 的评分状态能够独立确定为 `SCORED`、`REFUSED` 或 `INSUFFICIENT_EVIDENCE`；
7. 综合题没有被标记为整体无效；若整体无效，则所有绑定 item 均不能算有效测量机会。

因此：

```text
综合题绑定 item ≠ item 已被有效测量
综合题中存在独立证据 + 独立评分状态 = item 获得有效测量
```

## 2.3 表单事实不使用普通题的最低测量机会

`experience` 和 `qualification` 不进入普通对话题量，因此不使用普通题的 `item_minimum_valid_measurement` 规则。

它们应使用各自的事实采集状态，例如：

```text
FORM_SUBMITTED
FORM_VALIDATED
FACT_EXTRACTED
FACT_CONFIRMED
FACT_MISSING
FACT_HUMAN_REVIEW
```

不能因为候选人填写了表单，就把 hard/soft 普通题 item 标记为已测量；反过来也不能因为普通题回答很好，就自动覆盖 qualification gate。

# 3. 测评路径的正确表达

## 3.1 普通能力题路径

对一个普通 hard/soft item，候选路径可以表示为：

```text
选择 item
  ↓
激活 easy
  ↓
回答 / followup
  ↓
证据评估
  ├─ 证据不足 → followup，最多两次
  ├─ 仍不足/错误 → 降级或封存
  └─ 证据充分 → 允许进入 medium
  ↓
medium
  ↓
证据评估
  ├─ 证据不足 → 按规则保持/降级/封存
  └─ 证据充分且稳定 → 允许进入 hard
  ↓
hard
  ↓
达到该 item 的最高测量目标或合法终止
```

这里每个 `easy / medium / hard` 节点是否实际激活，取决于状态机；不是每个 item 必须走完三层。

## 3.2 综合题阶段

当普通题阶段达到策略规定的综合阶段入口时：

```text
普通 hard/soft 目标完成或合法封存
  ↓
检查 integrated_question_target
  ↓
激活综合题 1（若策略需要且题目有效）
  ↓
评估各绑定 item 的独立证据
  ↓
根据剩余联合 target 决定是否激活综合题 2
  ↓
结束综合阶段
  ↓
进入终局评分和报告
```

综合题不是自动接在每个 item 的 hard 题之后，而是在普通题阶段之后的独立阶段。

## 3.3 `followup` 的位置

`followup` 只存在于当前题内部：

```text
同一 assessment_question 实例
├── 首次回答
├── followup-1
└── followup-2
```

它：

- 不增加普通主问题配额；
- 不增加综合题槽位；
- 不改变 `question_bank` 题目；
- 不算新的 difficulty 节点；
- 只补充当前题的证据。

# 4. “难度递进题”这个说法应删除

本轮明确：不再使用“难度递进题是否占基础配额”这种表述，因为它暗示难度升级会凭空产生一个额外题量类别。

后续统一使用：

- `difficulty_path`：某个 item 实际经过的难度路径，例如 `easy → medium → hard`；
- `ordinary_question_count`：实际激活的普通主问题数量；
- `integrated_question_count`：实际激活的综合题数量；
- `required_quota_exception_count`：required 刚性例外新增的普通主问题数量。

需要继续确认的不是“难度题算不算配额”，而是：

1. 一个 item 从 easy 进入 medium 时，是继续使用同一个 `assessment_question` 实例改变其阶段，还是创建一个新的题目实例；
2. 如果 easy、medium、hard 是题库中的三道不同题，它们是否分别计作三道普通主问题；
3. 如果同一个题面只是改变难度标签，是否允许这样建模；
4. 综合题是否可以作为普通题阶段的合法终止条件，还是必须单独进入综合阶段。

**当前建议：**每一个实际呈现给候选人的不同题面都创建一个新的 `assessment_question` 实例；同一题的 followup 不创建新实例。难度路径记录在同一 `session × item` 的导航状态中。

# 5. 普通主问题数量、综合题数量和 required 例外的关系

建议把 session 题量拆成三项，而不是用一个 `N_actual` 混合：

```text
ordinary_plan_count = N
ordinary_exception_count = E
integrated_plan_count = I

ordinary_actual_count = N + E
integrated_actual_count ≤ min(I, 2)

session_question_count
= ordinary_actual_count + integrated_actual_count
+ followup_count（仅用于交互轮次统计，不计主问题）
```

其中：

- `N`：按 hard/soft 7:3 基础比例和岗位策略生成的普通主问题计划数量；
- `E`：required 未覆盖导致的额外普通主问题数量；
- `I`：独立综合题槽位计划，最多两题；
- `followup_count`：只用于过程审计和成本统计，不进入主问题数量。

综合题不占 `N`，required 例外也不应改变 item.weight；三者分别统计、分别报告。

# 7. 后续 Prompt 对齐提醒

上一轮已确认下一轮需要逐项处理所有 LLM Prompt。当前与本轮最直接相关的 Prompt 候选包括：

- 回答状态分类；
- 证据覆盖与 `item_minimum_valid_measurement` 判断；
- 难度升级/降级建议；
- 综合题多 item 证据拆分；
- 综合题是否覆盖联合 measurement target；
- `MODEL_UNCERTAIN` 与 `ITEM_INVALID` 判断；
- 缺失/拒答/脚手架事件对终局评分的影响。

但 Prompt 不能直接决定：

- 题量配额；
- hard/soft 7:3；
- 综合题槽位；
- required 例外；
- 状态机最终迁移；
- item.weight；
- 最终报告是否发布。
